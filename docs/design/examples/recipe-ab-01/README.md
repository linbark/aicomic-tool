# 同内容 · 两配方 · 两成品

先只看匿名截图：[A](review-v2/A.png) · [B](review-v2/B.png)。匿名包在[评审目录](review-v2/manifest.json)对应的四个文件中，不含配方、丹药、材料或旧评分。它只保证导出投影匿名，不能保证评审者此前没有看过实现或配方。

## 本次控制了什么

- 同一份[18 条正文](content.json)，两页面文字及顺序一致，没有真实产品数据，页尾明确标为概念占位。
- 同一份[生成/捕获条件](conditions.json)，同会话编码 agent、同 light 主题、同 1200×1600 视口、DPR 1、同系统字体族、无外链资源和脚本。
- 从隔离副本中的同一素材重新计算色板与间距，冻结为两颗丹药。配方分别是[平静单列](minimal.recipe.json)与[编辑式层级](editorial.recipe.json)，包含不同配比及明确的排版参数；这些字号参数不是冒充从素材精确测出的数值。
- 两份 HTML 由编码 agent 按冻结规格分别实现：[实现一](minimal.html)、[实现二](editorial.html)。引擎只负责规格、捕获和证据，不内置固定页面生成模板。

## 实际执行结果

使用 release CLI 的 `create → attach ×2 → blind → record(demo) → stats` 完整运行。两图由本机 Google Chrome 157.0.8103.51 受控捕获，profile 相同，源码正文覆盖与冻结规格静态检查通过；已打开实际 PNG 检查排版。

真实浏览器验证发现过 Blink 全局禁脚本同时阻断 Chrome 截图的问题，已保留页面 CSP 脚本禁用并修复捕获调用。截图审阅还发现标题断词，修改后新建了第二次实验，旧实验与证据未被覆盖。

[证据摘要](evidence.json)包含页面/截图/profile/冻结规格/匿名清单的哈希与检查结果，不包含本机数据路径。样例只写入 `source=demo` 的弃权记录，用于证明命令链路和隔离；**正式真人实验数、评分人数、评价数均为 0，不得推断哪份更美。** 没有调用付费或真实生成模型，也未改原始用户数据库。

## 如何继续评价

- 评审者只看 A/B 截图与[共同规则](review-v2/manifest.json)，可选 A、B、tie 或 abstain。
- 只有用户本人明确提交时才用 `--source human --reviewer <本人>`。助手试填一律 demo；人评记录也不能直接当成某个人的内核训练数据，仍需明确个人用途和身份。
- 回流按完整配方定义 hash × 共同条件 hash × 规则分组，不拿文字机器分或静态通过当视觉分，不自动修改药液质量。
- 此处 HTML/PNG 可以直接查看；复跑 CLI 需在自己的独立数据库准备相应冻结丹药，不能假设别人的本地 ID 也为 30/31。命令说明见[研究 CLI](../../../../inspiration/README.md)。

## 边界

源码文字/媒体覆盖不等于完整 DOM 可见性证明；生成条件是操作者声明，非独立执行认证；受控截图不是数字签名或 OS 网络沙箱。字体依赖本机环境，尚未验证 Windows/Linux。当前只覆盖静态 HTML 成品，不代表真实交互、动效、视频或跨领域审美已验证。两页面按不同配方实现，生成过程并非可重复随机实验，不能据一组比较宣称因果或普遍优劣。
