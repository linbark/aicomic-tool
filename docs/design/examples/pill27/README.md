## 缺口对比：8 条 → 6 条

**已关闭（3 条）**

| 原缺口 | 现在 |
| --- | --- |
| 版式骨架是无效值（`COOLEST`） | `单列`（枚举生效） |
| 字号比例不可执行（1.5:1） | `display 72px/600`、`body 18px/400` |
| 间距无值 | `8px 模数 / 档位 8,16,24,32 / 页边 181 / 段距 64` |
| 颜色没有角色 | `底 #FDFCFD、字 #2B2B2B、强调 #90A1A2、线 #DBE0E1` |

**仍开放（6 条）**

| # | 缺口 | 说明 |
| --- | --- | --- |
| 1 | 禁忌仍"就图论图" | 仍在说「模糊背景国旗图标」，`applies_to` 只标了语境，没做抽象 |
| 2 | **间距与模数不自洽** | 页边 181px 不是 8 的倍数——测量结果自己就违反了模数 |
| 3 | 组件状态缺失 | hover/focus/disabled/空态仍无规格 |
| 4 | 响应式断点缺失 | 我自定 760px |
| 5 | 文案缺失 | 产品名、主张、指标仍是我编的 |
| 6 | 验收只有静态特征 | 颜色/阴影/对比/字号四项，没有视觉与可用性检查 |

**新增的发现**：第 2 条是这轮改动引入的新问题——像素测量的页边（181）与模数（8）来自两套算法，
彼此不校验。修法很简单：把页边吸附到模数的整数倍，或者干脆承认"页边是独立 token，不必服从模数"。

## 结论

数值化确实把"生成器要自己猜"的范围压小了，但**规格自身的自洽性成了新问题**。
下一步要么加约束求解（让 token 之间互相校验），要么承认"规格是分层的，层内自洽、层间可冲突"。
