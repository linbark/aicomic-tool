# 炼丹炉可信基础 · 第一阶段验收

> 2026-11-12。承接[进度快照](炼丹炉进度快照-2026-11-12.md)，本阶段只修可信基础，不宣称成品审美或真实个人学习已经闭环。

## 1. 已实现的行为

| 范围 | 行为与边界 |
| --- | --- |
| 评分来源 | 明确区分 human / ai / demo / legacy；旧分不删、不猜评分者，全部隔离为 legacy；未指定来源默认 demo |
| 真人确认 | human 必须显式提供非空 reviewer；只有真实来源才参与当前最终分、关闭人工任务或作为校准证据 |
| 演示隔离 | demo / ai / legacy 不能覆盖已经接受的真人评分；演示不改真人判断，也不能假装人工任务已完成 |
| 批量事务 | 整批解析校验后写入，评分、审核历史、最终分和队列状态同事务；非法后项、重复标签、NaN/Inf、越界、重算异常均回滚 |
| 校准 | 同一评分者的真实成对评分才计数；旧权重存档且不再自动应用；少于 20 对只显示统计，不应用建议权重；无真样本恢复默认权重 |
| 一屏审阅 | 支持单裁判 win_i 与合议 combined/votes/disputed；显示评分来源、审核人、时间、维度，不再把合议结果全部误显示成平局 |
| 药液版本 | 追加式不可变记录；refresh 创建新 revision；缓存身份覆盖手法版本、提示词、参数、契约、素材真实字节与执行输入 |
| 当前药液 | 当前 head 与历史内容分离；缓存命中旧 ID 也可成为当前 head；不自动挑过时契约的药液 |
| 丹方输入 | 直接钉住本次 refine 实际返回的药液，不再通过 max(id) 猜测是哪瓶 |
| 历史快照 | 新丹药冻结完整配方定义和药液内容、版本、revision、hash、输入；简报、验收、重评读取冻结依据 |
| 旧丹药 | 默认不读活药液来冒充历史，明确标记历史不可复原；显式 legacy fallback 也不得通过历史可复现性验收 |
| 数据升级 | 新增显式 migrate 命令，嵌入 SQL、升级前一致性备份、单事务迁移、外键核验和失败回滚；拒绝未知/更新格式，不静默升级默认库 |

历史可复原只指规格和验收依据被冻结，不保证再次调用生成模型能得到相同页面。原有历史 final_total/final_json 保留供审计；新重算不再消费来源未知的旧分。

## 2. 使用方式

从仓库根目录运行构建后的 CLI：

```sh
# 必须显式升级用户选择的库；已有库先创建相邻 .bak 备份
./inspiration/target/release/ie migrate --db /absolute/path/to/my.db

# AI 或演示回填不得使用 human
./inspiration/target/release/ie judge fill --db /absolute/path/to/my.db \
  --run 1 --scores "A=82,B=70" --source demo

# 只有用户本人真实输入才使用 human
./inspiration/target/release/ie judge fill --db /absolute/path/to/my.db \
  --run 1 --scores "A=82,B=70" --source human --reviewer me --dimension hierarchy

./inspiration/target/release/ie judge screen --db /absolute/path/to/my.db --run 1
./inspiration/target/release/ie judge calibrate --db /absolute/path/to/my.db
./inspiration/target/release/ie judge models --db /absolute/path/to/my.db
```

升级不为旧药液猜测新版输入身份。要参与自动选药，相关材料需按当前手法重新 refine；旧药液与旧背包记录仍完整保留。

## 3. 回归证据

已实跑完整独立 workspace：**36 个单元/模块行为测试 + 5 个 CLI 集成测试，合计 41 个通过**。关键覆盖：

- 非法后项、重复标签、非有限数值与数据库重算故障不留半批数据。
- demo/legacy 不进入真实校准；不同评分者不拼成一对；20 对阈值；默认权重与旧权重隔离。
- demo/AI 不覆盖已接受真人分；审核来源/时间/维度与追加历史可查。
- 版本升级、契约/参数/素材变化、refresh 都不改写旧药液。
- A → B → 缓存 A 后选药及丹方确实使用 A，不误取最大 ID 的 B。
- 旧库升级保留药液 ID、NULL/旧版本、背包 owner/qty/note/time、丹药到配方/丹方的关联。
- 历史药液拒绝 UPDATE/DELETE；冻结丹药导入无药液的独立库后，仍能出简报并按冻结色板验收。
- 改写当前配方不会改变旧冻结丹药的重评完整度。
- 新库初始化、重复迁移、升级备份、外键异常全量回滚、未知库保护、旧 schema 写入门禁。

同时实际执行并通过：`cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets --locked --offline -- -D warnings`、`cargo build --release --locked --offline`。

测试为内存库或独立临时文件与生成素材，不请求真实模型，不需要 API 密钥。此结果不代表星晴根 workspace、Windows 或远端 CI 已经验证。

## 5. 仍然开放的边界

1. 机器成对评判尚无逐对检查点与断点恢复；没有新增这一承诺。
2. BT 是批次内相对强度，不能冒充绝对审美质量；合议与预检也不等于成品评分。
3. 20 对是工程门槛，不证明统计可靠；校准仍需进一步按个人、维度和模型版本拆分。
4. 当前产物验收仍主要是源码启发式，不是浏览器视觉或交互验收。
5. 新炼丹/评判表的完整跨库导入导出、真实交互素材、动效品质尚未完成。
6. 成品结果回流与真实个人内核驱动选药，是接下来的第二、第三阶段。
