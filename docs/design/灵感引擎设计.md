# 灵感引擎设计

> 设计稿 v1.1 ｜ 2026-11-10 ｜ 取代 v0.1（UI 专用，已归档）｜ DDL：[schema.v2.sql](inspiration/schema.v2.sql) ｜ 个人层：[迁移 002](inspiration/migrations/002-personal-layer.sql) ｜ 词表：[packs/](inspiration/packs/) ｜ 数据源：[Designeer 接入规范](Designeer数据源接入.md)
>
> 本文设计的是**领域无关的灵感引擎**，UI 只是它的第一个领域包。文中数字分三类：标「实测」的来自 2026-11-10 的真实请求与真实建库；标「估算」的是推算；其余是设计假设，需要后续用数据检验。

## 0. 一页结论

UI 灵感库的天花板，是它只能回答"别的界面长什么样"。真正的灵感来自**别的领域如何解决同一个美学问题**：建筑用柱廊解决"等距重复如何不呆板"，音乐用休止解决"信息之间如何留出注意力"，摄影用框景解决"如何让人只看一处"。

灵感引擎把这件事做成可计算的三层：

```text
                ┌──────────── core 词表（跨域共享）────────────┐
                │  基元 primitive · 度量 metric · 语境 context  │
                └───────┬───────────────────────┬──────────────┘
        ┌───────────────┴──────┐        ┌───────┴────────────┐
        │ ui 包：间距阶/字阶/… │        │ 建筑包：柱廊/庭院/… │
        └───────────────┬──────┘        └───────┬────────────┘
                        └──── 手法 device ───────┘
                                   │
                    原则 principle（含反例与边界）
                                   │
                   规格 spec（目标领域的可执行方案）
```

- **提取**：作品 → 片段 → 观察 → 度量 → 手法归因 → 基元。不是给图片打标签，是把"它为什么好看"拆成可检查的机制。
- **使用**：按目标语境找**同域证据**，再按距离带找**异域手法**，迁移时给出机制、可行性、风险与反例。
- **创造**：把两个领域的手法在"类属空间"里融合，产出两个输入都没有的**涌现结构**，再落成规格。
- **个人**：面向 ToC 时再加一层——每个人用自己的判定训练**个人美学内核** `δ_p`。内核是跨语境不让渡的判断，风格（瑞士网格、侘寂、粗野主义）是可换的表达语言：**内核做硬约束，风格做软建议**。详见[个人美学内核设计](个人美学内核设计.md)。

三条硬规则（写进 schema，不靠自觉）：

1. **基元跨域共享，手法属于领域包。** 基元只能进 `core` 包，手法不能进 `core`（CHECK 强制），否则词表会随领域漂移成标签汤。
2. **没有反例或边界的原则不得发布。** 只有支持证据的"主张"是刻板印象。
3. **未富化的条目不得进入规格。** 只有 slug 没有标题的条目可以出现在检索结果里，但不能被规格引用。

一句诚实：**美不能被完全计算**。引擎建模的是"某人群在某语境下的审美响应分布"，输出永远是分布 + 语境 + 不确定性，不是"这幅图 87 分"。

**当前实测状态**：38 个跨域基元、10 个可测度量、22 个领域手法（UI 12 + 建筑 10）、6 个风格、**865 件真实作品**（841 条 UI 目录 + 24 件建筑照片，来自两个已跑通的源）、851 张素材已下载并完成像素抽取（`data/inspiration/`，本地未提交）：

- **M1 像素层已跑通**：810 件作品（UI 786 + 建筑 24）× 6 个基元（比例体系/对称/主动留白/明度对比/单色克制/细节密度）＝ 4860 条 `work_primitive`；851 张图解码成功率 100%，全量约 2.8 s；41 张空白海报（4.8%）被 `asset.blank` 拦下。
- **语义层已接通**：`ie vision` 走 Gemini（3.1-flash-lite / 3.5-flash），20 张试跑成功，产出 30+ 条手法与 50+ 条基元，全部落在词表内；单张约 2.9k token、2–18 s。全量 851 张待批准（约 2.45M token）。
- **P0 个人层已演练**：200 次合成判定 → 留出准确率 0.80、与真值 ρ=0.96、产出 L3 内核卡（非真实用户数据）。

手法层覆盖分析（与像素覆盖是两件事）：**7 个基元在两个领域都有手法，11 个只有 UI 手法，10 个只有建筑手法，10 个尚无任何手法**——这 31 条是迁移或新增手法的第一批待办。

## 1. 为什么不能停在"UI 灵感引擎"

| 失败模式 | 表现 | 根因 |
| --- | --- | --- |
| 领域绑定 | 越用越像同一个 UI 库，产出的界面互相像 | 语料只来自一个领域，先验就是该领域的均值 |
| 同域检索 | 输入"更高级一点"，只能返回更贵的同类网站 | 没有跨域结构，只能做邻近插值 |
| 标签汤 | 标签从 50 个涨到 5000 个，"高级感"和"高级"并存 | 自由标签没有词表治理，无法比较与迁移 |
| 单一评分 | 一个 0–100 的"美感分"决定一切 | 把分布压成标量，抹掉人群与语境差异 |
| 只有生成 | 每次从零生成，越生成越平庸 | 没有可积累的判断，只有一次性输出 |
| 只有参考 | 给一堆图，说不出为什么，也说不清何时不适用 | 参考是图片，不是可执行的论证 |

三个跃迁：

1. **从图库到判断库**：数据单位从"作品"变成"作品 + 观察 + 基元 + 原则"。
2. **从同域到跨域**：检索单位从"像这张图"变成"实现了同一个基元的另一种手法"。
3. **从生成到创造**：交付物从"图"变成"规格 + 论证 + 组合方案"，图只是最后一步。

## 2. 美的可操作模型

### 2.1 立场

美不是物体的属性，是**观察者在语境中的响应**。同一件作品在婚礼请柬和核电站控制台上，审美价值不同；同一张海报对设计师和路人的"好看"也不同。所以引擎不存"美的分数"，只存：

- **成对比较**（A 比 B 好）：最可靠、最便宜、最不容易被绝对分数污染；
- **典范入选**（进了某个馆藏/年鉴/获奖名单）：权威但稀疏、有机构偏差；
- **落地结果**（被采用/被弃用/上线后表现）：真实但混杂无数非审美因素。

三者都进 `judgment` 表，带 `population`（人群）与 `context_json`（语境），用 Bradley-Terry 拟合出**分语境的偏好参数**。

### 2.2 四成分响应模型（设计假设，待检验）

```text
R(x | c) = C^α · K^β · exp(-(n-μ_n)²/2σ_n²) · exp(-(t-μ_t)²/2σ_t²)

C = 秩序（coherence）   对称、对位、比例体系、色调统一
K = 工艺（craft）       边缘精度、间距规整、曲线一致、时序平滑
n = 新意（novelty）     与领域典范质心的距离
t = 张力（tension）     明度/材质/尺度/密度差的总量
μ, σ 由语境 c 决定，来自成对比较拟合
```

两个**门槛**（不是加分项）：

- `C < c0`：再新也只觉得乱；
- `K < k0`：再对也觉得糙。

两个**倒 U**：

- 新意过低 → 陈词滥调；过高 → 无法解读（处理流畅性下降）；
- 张力过低 → 平庸；过高 → 疲劳。

这不是玄学，是 Berlyne 唤醒理论与处理流畅性研究的工程化写法：**美 ≈ 在可理解的秩序之上，施加恰到好处的新意与张力**。它是假设，不是定论——`preference_model` 表存参数与拟合指标，参数错了可以被数据推翻。

个人层用这个模型的局部线性近似来估"谁更喜欢哪一点"：`R(x|c,p) = (w_pop + Δ_c + δ_p)·φ(x)`，`φ` 含基元得分与四成分估计。理论模型负责解释，线性模型负责拟合，两者不是两套体系。

### 2.3 为什么必须是分布

如果只输出一个分数，引擎会自动学会"最安全的那一档"，也就是所有 AI 设计工具收敛到的那个均值。所以：

- 每个语境（领域 × 人群 × 媒介）一套 `μ, σ`；
- 个人版把人群先验拆成 `w_pop + Δ_c + δ_p`：`δ_p` 是跨语境不变的个人内核，`Δ_c` 是语境偏移（见[个人美学内核设计](个人美学内核设计.md) §2）；
- 输出带置信区间与样本量；
- 当同一作品在不同语境下排序相反时，引擎**记录冲突**而不是求平均——这正是 `variant` 存在的理由。

### 2.4 明确不建模的部分

意义、记忆、身份认同、时代精神、作者的意图——这些不进入模型，进入 `gap`。引擎宁可说"这一层我判断不了"，也不编一个 0.73 的分数。

## 3. 严格的数据体系

### 3.1 五级粒度

| 级 | 表 | 回答 | 例 |
| --- | --- | --- | --- |
| 作品 | `work` | 这是什么、谁做的、什么领域 | 一张海报 / 一栋建筑 / 一段界面 |
| 片段 | `fragment` | 局部在哪、是什么部位 | 海报右下角的字号层级 / 檐口 / 第 9–16 小节 |
| 观察 | `observation` | 抽取器看到了什么 | 栅格 12 列、字阶 1.25、圆角 3 档 |
| 度量 | `measure` | 可比较的数字 | 间距变异系数 0.08、留白率 0.42 |
| 判断 | `device_usage` / `principle` / `transfer` | 用了什么手法、什么条件下成立、能否迁移 | 柱廊→导航轨，可行性 0.7 |

片段层是领域无关的关键：基元经常只在局部成立（整个页面很乱，但那个空状态极好）。没有片段层，就只能给整张图贴标签，而这正是标签汤的起点。

### 3.2 词表治理

- `vocab_term` 分七类：`primitive / device / metric / context / style / medium / outcome`。
- `primitive` 只能在 `core` 包；`device` 只能在领域包（CHECK 强制）。
- 未入词表的自由标签只能进 `term_proposal`，人工/模型审核后才升级为词表项。**没有这条路，三个月后一定是标签汤**。
- 词表项只废弃不删除（`status='deprecated'`），历史证据仍然可解释。

### 3.3 证据与可重放

- 每条 `observation` 带 `extractor` + `extractor_version`，换模型后可重跑对比，不一致进 `review_queue`，不静默覆盖。
- 观察不可变：修正用 `supersedes_id` 指向前一条，保留演化史。
- 所有派生行都有来源路径：`measure → observation → asset/fragment → work → capture → source`。
- 证据分级：**A** 直接测量或高置信抽取；**B** 专家判断；**C** 模型提议。原则的置信度按 A/B/C 加权，C 级证据不能单独支撑一条已发布原则。

### 3.4 校验闸门

`validation_result` 存规则、严重度、消息；`ie validate` 可重跑。当前规则示例（实测 792 行结果）：

| 规则 | 严重度 | 含义 |
| --- | --- | --- |
| `title.enrichment` | info | 只有 slug 标题，不得进入 spec（791 条） |
| `source.reconcile` | warn | 上游声明数与发现数不一致（1 条） |
| `principle.publishable` | error | 支持 < 3 或跨域 < 2 或无反例/边界，禁止 `published` |
| `transfer.evidence` | error | `tested` 状态但证据 < 2 |

### 3.5 v1 → v2 的教训（已实测）

v1 按 UI 设计时，`work` 的唯一键是 `(source, collection, slug)`；v2 一开始写成 `(source, domain, slug)`，迁移 Designeer 数据时立刻撞上 `dev-chauhan`、`diar-muradi` 两个跨集合重名——**同一源的不同集合可以复用 slug**。这类错误只有真数据能暴露，所以设计文档里保留了这条：领域无关的模型不能假设 slug 在领域内唯一。

## 4. 跨领域涌现

### 4.1 用基元做枢纽，而不是领域两两连线

13 个领域两两建桥是 78 条边，且每条都要单独维护。基元是天然的枢纽：领域 → 手法 → 基元 ← 手法 ← 领域。加一个领域只需加一个包，所有既有基元自动获得新的手法来源。

### 4.2 距离带

灵感的价值与距离呈倒 U：

```text
d < 0.3   太近：换皮抄袭，用户看得出
0.3–0.6   可用：结构可迁移，表面不雷同   ← 目标带
d > 0.7   太远：只能当隐喻，落不了地
```

`d = 0.6 · domain_distance + 0.4 · (1 - primitive_overlap)`，其中 `domain_edge.distance` 手工标定并随证据修正（当前手工标定建筑↔UI 为 0.55，待证据修正）。目标带随语境调节：保守品牌往 0.3 压，实验性项目放到 0.7。

### 4.3 迁移（transfer）

一条迁移必须回答四件事，缺一不可：

| 要素 | 说明 | 反例（不合格的迁移） |
| --- | --- | --- |
| 共享机制 | 为什么它在两个领域都成立 | "都很有设计感" |
| 可行性 | 目标领域的成本/技术约束下能否实现 | 柱廊要求真实承重，界面没有承重 |
| 风险 | 迁移后可能失效的地方 | 移动端没有足够横向空间放柱廊节奏 |
| 证据 | 至少两个领域的作品实例 | 只有一句类比 |

当前 51 条 `primitive_link` 已经能自动生成候选：UI 的 `spacing-scale` 与建筑的 `colonnade` 都实现 `rhythm.equal`，机制都是"等距重复产生可预期节拍"，差异在材质与尺度——这就是一条待验证迁移。

### 4.4 融合（blend）是一等公民

两个输入空间 + 一个类属空间 → 融合空间。融合里**两个输入都没有的结构**才是灵感，必须显式记录（`emergent_json`），否则融合退化成拼贴。

工作示例（真实可用于规格）：

```text
输入 A：建筑庭院（arch.courtyard-void，实现 negative-space.active + rhythm.hold）
输入 B：音乐休止（rhythm.hold 的时间版）
类属空间：用一段有边界的空，让注意力重新对准主体
涌现结构：空不是"缺内容"，而是"一个需要被进入的房间"——入口动作本身就是内容
落成规格：空状态 = 一句解释 + 一个进入动作 + 由内容轨道围合出的边界；不得用插画填满
```

### 4.5 五个涌现算子

| 算子 | 做法 | 产出例 |
| --- | --- | --- |
| 缺口补全 | 目标领域某基元手法稀疏 → 从供体领域借 | UI 的 `depth.atmospheric` 只有 1 个手法 → 借摄影的空气透视做次级面板降饱和 |
| 反向迁移 | 把目标领域手法搬到供体领域检验 | 把"加载骨架屏"搬到展览设计：未完成的展陈作为叙事 |
| 尺度换位 | 同一手法放大/缩小一个数量级 | 柱廊 → 列表行；庭院 → 空状态 |
| 材质换位 | 结构不变，换媒介 | 纸的折痕 → 界面的折角投影 |
| 约束移植 | 借用供体领域的硬约束 | "单色印刷"约束 → 单色仪表盘 |

### 4.6 反同质化

- 新颖度下限：规格里至少一条手法来自目标领域之外，或明确说明为什么不用。
- 多样性配额：一次灵感会话里，同一基元的方案不超过 2 个。
- 偏差登记：`source.policy_json.bias` 记录每个源的审美偏差，规格输出附带。

## 5. 数据模型 v2

DDL 见 [schema.v2.sql](inspiration/schema.v2.sql)，已在 SQLite 3.54 上实测：建表、CHECK、触发器（错误 kind 写入会被 ABORT）、外键、视图、FTS 全部通过；真实数据 841 条导入后 `integrity_check=ok`、`foreign_key_check` 为空。

| 组 | 表 | 关键设计 |
| --- | --- | --- |
| 词表 | `pack`, `vocab_term`, `term_proposal` | core/领域分离，提案队列防标签汤 |
| 领域 | `domain`, `domain_edge` | 包与领域 1:1；领域距离可修正 |
| 来源 | `source`, `fetch_run`, `capture` | 内容哈希去重，抓取可重放 |
| 作品 | `work`, `asset`, `fragment`, `work_tag` | 片段层支持局部基元 |
| 观察 | `observation`, `measure` | 不可变 + 版本化抽取器 |
| 结构 | `primitive_link`, `device_usage`, `transfer` | 手法↔基元↔跨域迁移 |
| 判断 | `principle`, `principle_scope`, `principle_evidence`, `judgment`, `preference_model` | 原则必须带边界；判美只用相对信号 |
| 创造 | `blend`, `spec`, `spec_principle`, `spec_device` | 涌现结构与规格分离 |
| 质量 | `validation_result`, `review_queue`, `feedback`, `embedding` | 闸门 + 学习信号 |
| 检索 | `search_doc` + `search_fts` | 单索引覆盖四类对象，中文靠分词列 |
| 个人 | `person`, `kernel`, `kernel_claim`, `pair_task`, `style*`, `judgment.actor_id` | ToC 层，见[个人美学内核设计](个人美学内核设计.md) §8 |

为什么不是一张万能表：每张表回答一个不同的问题（谁给的 / 看到了什么 / 什么条件下成立 / 能不能迁移 / 用在哪）。合并会立刻出现"可空字段爆炸"，而可空字段是数据腐败的入口。

## 6. AI 驱动：提取、使用、创造

### 6.1 提取：验收标准是"重建"

抽取质量不能靠人看图点头。**重建测试**：

1. 用抽取结果生成规格（只有基元、手法、度量、片段描述，不给原图）；
2. 让生成模型按规格重建 3 个变体；
3. 盲评：原图 + 3 变体，请评审选出"最像原图气质"的一张；
4. 若原图被认出 < 70%，说明抽取漏掉了关键机制，回到第 1 步补。

这比"抽取准确率"更硬：它检验的是**抽取出的描述是否足以复现美学效果**，而不是标签是否看起来合理。首批样本选 163 条 finds（真实设计师作品、有海报、无描述），50 条做重建测试，其余做规模化标注。

### 6.2 使用：三层检索

| 层 | 范围 | 用途 | 排序主项 |
| --- | --- | --- | --- |
| 同域 | 目标领域包 | 找同类证据、建立基线 | BM25 + 向量 + facet |
| 邻域 | 距离 0.4–0.6 | 找可迁移手法 | 基元命中 + 可行性 |
| 远域 | 距离 > 0.6 | 找隐喻与结构 | 机制清晰度 + 新颖度收益 |

### 6.3 创造：交付"论证"而不是"图"

`ie spec` 的输出必须包含：选了哪条原则、依据哪几件作品、拒绝了哪条备选、为什么、哪个位置没有依据（`gap`）。规格是给人看也是给 Agent 看的——它同时是可执行方案和可审计记录。

### 6.4 判美模型的训练与校准

- 数据：成对比较，同一语境下每题 2 张，30 秒内可判；
- 模型：Bradley-Terry（带语境分层），样本 < 200 时退化为上下文先验 + 文案解释；
- 校准：报告 pairwise 准确率与 ECE，不只报准确率；
- 更新：新判断进库后重拟合，旧参数保留版本（`preference_model.fitted_at`）。

### 6.5 成本

vision 抽取按张计费，所以先做目录层筛选再抽取；批量 20 张/次；结果按 `(asset, extractor, version)` 缓存。判美靠人，成本更高，所以只对"要进规格的候选"做判美。

## 7. 检索与排序

```text
score = 0.35·bm25 + 0.30·cos + 0.15·primitive_hit
      + 0.10·band(d) + 0.10·(novelty_gain · feasibility)

band(d) = 1 - |d - 0.45| / 0.45          # 峰值在 0.45，两侧衰减
```

- `primitive_hit`：查询命中的基元在候选里被手法实现的程度；
- `novelty_gain`：相对目标领域典范质心的距离增量；
- `feasibility`：迁移可行性，来自 `transfer` 或现场估计；
- 最后做 MMR（λ=0.7）去重，并对同一基元限流；
- `--as me` 时把 `δ_p` 加进打分，并用内核的 `floor`/`avoid` 做硬过滤——**内核是不可让渡的约束，风格才是排序偏好**。

每条结果必须能回答"为什么给你看这个"：一句机制 + 一条证据 + 一条风险。

## 9. DSH 接入

方案不变（v1：Rust CLI + skill；v2：plugin），但 skill 的流程升级为四步：

```markdown
1. 定位：`ie spec --profile` 取规格；没有 profile 先问领域/受众/媒介。
2. 借形：`ie inspire --to <domain> --from <2 donors>`，先看迁移与风险，不要直接抄图。
3. 落定：规格里每条必须能追到原则或证据；`gap` 交给人决定。
4. 复盘：`ie critique` 自查 + `ie record` 回灌偏好。
```

关键点：skill 里不写"要好看"，写"要先借形再落定"——**流程约束比形容词有效**。

## 10. 领域包规范

```text
pack.json
  domain      {id, title, medium}
  devices[]   {term, label, realizes[], mechanism, observable, extract[]}
  styles[]    {term, label, definition}
  sources[]   {id, tier, note}
  spec_template {sections[]}
```

生命周期：`draft`（只有词表）→ `trial`（≥20 件作品、≥3 条原则、1 次重建测试）→ `stable`（≥100 件作品、跨域迁移被采用 ≥3 次）→ `deprecated`。升降级由 `validation_result` + 使用反馈决定，不靠拍脑袋。

当前两个包：`ui`（12 手法、3 风格、841 作品）与 `architecture`（10 手法、3 风格、待接入作品）。两者共享 7 个基元；11 条只有 UI 手法、10 条只有建筑手法、10 条尚无任何手法——这三类合计 31 条，都是迁移或新增手法的待办。

## 11. 数据源地图

优先**开放许可 + 有 API** 的源，因为它们能合法地进入本地库并长期复用：

| 领域 | 候选源 | 许可 | 可达性（实测 2026-11-10） |
| --- | --- | --- | --- |
| 产品界面 | Designeer | 目录可引用 | 200（详情被 403，见接入规范） |
| 艺术 | Met Open Access | CC0 元数据 | **200** |
| 艺术 | Art Institute of Chicago | CC0 元数据 | 403（需再核） |
| 设计/工艺 | Cooper Hewitt | CC0 元数据 | 404（端点已变） |
| 工艺/纺织 | Rijksmuseum | 开放 | 410（旧 API 下线） |
| 音乐 | MusicBrainz | CC0 | **200** |
| 自然/生物形态 | iNaturalist | CC BY-NC | **200** |
| 建筑/摄影 | Wikimedia Commons | 逐条（CC0/CC BY/CC BY-SA） | **200**，已接入 24 件 |
| 文本节奏 | Project Gutenberg | 公有领域 | 未测（第三方镜像 gutendex 超时） |

已在 Commons 上实跑一次建筑语料接入：3 个分类（柱廊/庭院/粗野主义）各取 8 件，24 件全部入库并记录逐条许可（CC0 2、公有领域 7、CC BY 系列 6、CC BY-SA 8、无限制 1）。这批数据同时暴露了一个真问题：**分类目录不等于精选样本**——分类里混进了同题材的绘画，需要用重建测试与人工评审挑掉，不能直接把"某个分类的全部文件"当成一个领域的典范集。

结论：**可达性必须在运行时验证，不能写在代码里**。`source.policy_json.reachable` 由每次 `sync` 更新，不可达的源自动降级并记 `validation_result`。这也是"严格数据体系"的一部分：数据源本身是会被验证的对象。

## 12. 评测

| 维度 | 方法 | 门槛 |

## 14. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 审美霸权 | 引擎把一种文化口味当普世标准 | 分语境参数 + 偏差登记 + 输出不确定性 |
| 词表膨胀 | 基元从 38 涨到 300，失去可比性 | 提案队列 + 合并评审 + 只废弃不删除 |
| 原则空话化 | "要平衡、要有节奏"这类无法执行的主张 | 发布闸门要求可检查的 `observable` 与反例 |
| 判美成本 | 人评不够，模型自评有偏 | 少样本 + 主动学习挑最有信息量的对 |
| 版权 | 作品图不可再分发 | 本地缓存、对外只给引用；优先 CC0 源 |
| 过度抽象 | 跨域迁移变成牵强类比 | 距离带 + 可行性门槛 + 风险必填 |
| 数据源失效 | API 下线、站点改版 | 运行时可达性验证 + 多源冗余 |
| 过度断言 | 几十次比较就被说成"人格" | 成熟度阶梯 + 强制不确定项 |
| 审美茧房 | 只推荐已喜欢的，越用越窄 | 15% 探索位 + 分歧地图 |
| 隐私 | 截图泄露偏好 | 本地优先，只上传抽象判定 |

## 15. 待决问题

1. 第三领域选哪个？**摄影**最省成本（图像模态与现有管线一致、开放源多），**音乐**最能拉开跨域距离（但需要音频抽取器）。建议先摄影验证机制，再音乐验证远域。
2. 判美样本从哪来？自评会引入个人偏差，公开偏好数据集又多为人像/摄影。建议先做 200 对内部专家判断，作为 v0 参数，再逐步扩。
3. 引擎是否直接产出图像？建议 v1 只产出规格与组合方案，图像交给下游生成器——否则引擎会被"出图好不好看"绑架，回到图库逻辑。
4. 本地优先还是云端语料？本地优先符合隐私与版权，但跨领域语料的构建成本高。建议本地库 + 可选共享的**不含图片**的元数据/原则层。
5. 个人层先做还是先做 M1 提取？提取决定语料质量，个人层决定产品形态。建议先提取 200 条基线数据，再让个人层在其上学习——否则用户在一堆没有基元标注的作品上做选择，学不到 `δ_p`。
