## 0. 术语

| 术语 | 含义 |
| --- | --- |
| 漫剧 | 以漫画/插画画面为主体、配合配音与镜头运动讲述连续剧情的短剧形态 |
| 动态漫 | 静态画面分层 + 视差/局部动效 + 配音的轻量动态化，成本低、稳定性高 |
| 分镜（Shot List） | 把剧本拆成一镜一行的结构化镜头表，是画面、时长、台词、运镜、连续性的唯一载体 |
| 运镜 | 机位与镜头的光学运动：推、拉、摇、移、跟、升降、环绕、手持、变焦、变焦推拉（希区柯克变焦）等 |
| 首尾帧 | 为同一镜头提供起始帧与结束帧，由视频模型插值生成中间运动 |
| 连续性锁 | 一条可原样粘进提示词的固定短语，用来跨镜、跨集锁定造型/场景/道具 |
| 闸门（Gate） | 流水线中必须由人确认才能继续的检查点 |
| 配方（Recipe） | 把"某一类片子的做法"固化成可复用的阶段组合与参数预设 |

## 1. 结论摘要

1. **没有"一键成剧"**。所有成熟项目都把制作拆成"资产先行 → 分镜驱动 → 批量生成 → 后期缝合"，一次性生成整集的结果必然崩人设、崩画风、崩时长。
2. **分镜表是中枢**。画面类型、时长、台词、运镜、参考图、连续性全部挂在镜头行上；分镜写不好，后面所有环节失控。
3. **一致性靠工程手段，不靠运气**：角色三/四视图 + 固定提示词段落 + 参考图注入（LoRA/IP-Adapter/FaceID/ControlNet）+ 固定种子 + 资产库版本。
4. **生成要"动得少"**：单镜 2–5 秒，优先呼吸、眨眼、轻微推拉、发丝飘动；大幅肢体动作交给分镜和剪辑绕开。
5. **干预必须前置**：在分章、资产、分镜、首帧四处设闸门，比成片后返工便宜一个数量级；生成前先出预览与报价，确认后再花钱。
6. **队列、幂等、版本是量产的地基**：任务持久化、供应商任务 ID、内容哈希命名、断点续跑、只取消排队任务、重新生成不覆盖旧版本。
7. **批量拼的是一次通过率**，不是单条效果。并发、资产库、合格率、单片成本四项决定盈亏；调度错误带进批量会被复制成几十批废片。
8. **两条技术路线长期并存**：动态漫（关键帧 + 视差 + 配音）负责稳定量产，视频生成负责打斗与情绪爆点。

### 1.1 对星晴的决策速览

研究结论不等于产品范围。星晴是 Rust 原生、单机、无 WebView/本地 HTTP 的桌面应用，当前只有文本模型、运行记录与资产库，没有图像/视频生成执行器。据此把研究结论分成三类：

| 研究结论 | 星晴决策 | 状态 | 设计文档对应 |
| --- | --- | --- | --- |
| 分镜表是中枢，画面/时长/台词/运镜都挂在镜头上 | 先让分镜成为可见、可检查的产物（`shots` JSON），再逐步落库 | 已实现产物级 | §3.1、§3.4 |
| 资产先行，未冻结不批量 | 引入项目级"资产冻结"闸门；资产变更自动解除冻结 | 已实现 | §3.2、§5.4 |
| 干预前置，成片后返工最贵 | 五道闸门：大纲、剧本、结构、资产、分镜；所有生成先确认 | 已实现 | §3.2、§5.6 |
| 一致性靠工程手段，不靠运气 | 分镜生成注入已确认的 Visual DNA；提示词由受控字段编译 | 部分实现 | §3.4、§5.3 |
| 生成要"动得少"，单镜 2–5 秒 | 分镜阶段保留时长预算；生成执行不在本期 | 暂缓 | §3.1、§9 |
| 队列、幂等、版本是量产地基 | 沿用 Run/Stage、待写入重试、不覆盖旧产物；持久任务表后续 | 部分实现 | §3.5、§9 |
| 批量拼的是一次通过率 | 没有合格率与幂等前不开放批量 | 明确不做 | §2、§8.2 |
| 动态漫优先，视频当"贵镜头" | 路线采纳；合成与视频在 P4 之后 | 暂缓 | §9 |
| 剪映草稿比 mp4 更有交付价值 | 需要稳定版本适配与真实用户验证 | 未决 | §10 |
| 不做"一键生成整集" | 作为产品红线：只做分阶段、可确认、可回溯 | 已采纳 | §2、§8.2 |

## 3. 两条技术路线

| 维度 | 动态漫 / 静态漫剧 | AI 视频漫剧 | 混合 |
| --- | --- | --- | --- |
| 画面 | 关键帧 + 分层视差 + 局部动效 | 图生视频 / 首尾帧插值 | 文戏静态、武戏生成 |
| 单镜成本 | 低（只有图 + TTS） | 高（按秒计费） | 可控 |
| 稳定性 | 高，人设/构图可控 | 中，长动作易崩 | 高 |
| 表现力上限 | 中 | 高 | 高 |
| 适合 | 日更、对话戏、旁白叙事 | 打斗、情绪爆点、预告 | 大多数商业项目 |

实践要点：**先跑通动态漫，再把视频生成当"贵镜头"按需插入**。这也是 drama-skills 把"静态漫剧"单列为一条路径、跳过视频提示词的原因。

## 4. 标准流水线

```text
原文 / 大纲
   │ 分析、分章、可拍性判断
   ▼
分集规划 ─► 剧本 ─► 资产（角色 / 场景 / 道具 / 声线）
                      │ 冻结（闸门）
                      ▼
                   分镜表（Shot 中枢）
                      │
      ┌───────────────┼─────────────────┐
      ▼               ▼                 ▼
   关键帧          配音 / TTS         BGM / 音效
      ▼               │                 │
   视频片段 ──────────┴─────────────────┘
                      ▼
                剪辑 / 合成 / 导出
                      ▼
                审片 / 发布
```

| 阶段 | 输入 | 产物 | 可自动化 | 人工闸门 | 典型故障 |
| --- | --- | --- | --- | --- | --- |
| 0 选题 | IP/题材/平台 | 卖点、禁忌、参考片单 | 爆款检索、对标拆解 | 选题决策 | 同质化、无差异化 |
| 1 原文分析 | 小说/大纲 | 章节索引、人物关系、可拍性问题 | LLM 抽样快评 | 是否全量拆 | 章节当集数、主线丢失 |
| 2 分集 | 分析结果 | 分集地图、钩子、情绪弧 | 节拍模板 | 分集方案 | 节奏平、集尾无钩子 |
| 3 剧本 | 分集方案 | 可拍剧本（场次/动作/对白/OS/VO/时长） | 写作 + 业务审 + 合规审 | 剧本定稿 | 心理描写不可拍、台词超长 |
| 4 资产 | 剧本 | 角色三/四视图、场景、道具、声线 | 批量出图、参考图注入 | **资产冻结** | 人设漂移、风格漂移 |
| 5 分镜 | 剧本 + 资产 | 镜头表（景别/机位/运镜/时长/台词/连续性） | 拆镜 + 导演审镜 | 分镜定稿 | 越轴、时长对不上、镜头不可拍 |
| 6 关键帧 | 分镜 + 资产 | 每镜首帧（可选尾帧） | 批量出图 | 首帧抽检 | 崩脸、构图错、参考图失效 |
| 7 视频 | 关键帧 + 运镜 | 每镜片段 | 图生视频/首尾帧 | 片段抽检 | 大动作崩、时长漂移 |
| 8 配音 | 台词 + 声线 | 逐句音频、SRT、BGM | TTS、时长回填 | 听审定音色 | 音色不统一、赶词、口型错位 |
| 9 合成 | 片段/音频/字幕 | 成片 mp4 / 剪映草稿 | ffmpeg 拼接、字幕烧录 | 成片审 | 音画不同步、响度不达标 |
| 10 发布 | 成片 | 封面、标题、AI 标识 | 转码、压制 | 合规检查 | 平台限流、版权风险 |

## 5. 小说转剧本

### 5.1 分集原则

- **按冲突单元切，不按章节切**。章节数直接当集数是最常见的错误。
- 每集先定"核心冲突 + 集尾钩子 + 情绪落点"，再写正文；drama-skills 要求先出分集地图、导演阐述，再写单集。
- 短篇漫剧单集常见 90–120 秒；传统短剧单集 1–3 分钟。剧本阶段就把时长预算写死，否则后期全是删减。

### 5.2 内容模式决定剧本格式

ArcReel 的做法值得直接借鉴：同一份原文，先选内容模式，再决定剧本长什么样。

| 模式 | 剧本单元 | 适用 |
| --- | --- | --- |
| 旁白解说 | 旁白片段 + 对应画面 | 小说推文、解说流，成本最低 |
| 剧情演绎 | 场次 + 对白 + 动作 | 正剧、对话戏，需要表演与口型 |
| 参考生视频 | 视频单元 + 参考图职责 | 打斗、大场面，按视频能力拆分 |

### 5.3 节拍与时长

- 15 秒一个情绪单元，90/105/120 秒一集是常见档位；每个单元结尾要留下可承接的动作、视线、声音或道具钩子（TapCanvas 的 `exitState` 思路）。
- 对白密度要估：drama-skills 在小样本上实测，中文约 **4.1 个可发声字/秒**，超了会赶词或被截断。分镜阶段先估台词时长，再定镜头时长。

### 5.4 可拍化改写

把"她感到绝望"改成"她盯着凉透的粥，手指把勺柄捏出白痕"。novel-to-script-team 专门设了 `visual-storyteller` 做 Show Don't Tell 审核，这是剧本阶段性价比最高的一道检查。

### 5.5 剧本格式

- 场次标题（地点 + 时间 + 内外景）、动作行、对白行三段式。
- 对白标记：`角色（OS）` 内心独白、`角色（VO）` 画外音、`角色（情绪）` 带情绪台词；空镜/闪回/字幕用 `【】` 标记。
- 正文镜头行以 `△` 开头，便于机器拆分（TapCanvas 规范）。
- 也可用 Fountain 格式，DramaClaw 的结构化导入支持它。

### 5.6 双审与连续性账本

- **业务审**：结构完整性、钩子、留存点、爽点/虐点。
- **合规审**：平台边界、版权、低俗/血腥/未成年人风险。
- **连续性记录**：称呼、人设、道具、时间线、伏笔、设定变化。长项目跨集漂移是主要质量事故来源。

## 6. 分镜与运镜

### 6.1 分镜卡字段

| 字段 | 写什么 |
| --- | --- |
| 叙事作用 | 建立/推进/高潮/收束/过渡，或特写、细节、反应、插入、空镜、主观视角 |
| 节奏 | 慢、中、快 |
| 场景 | 在哪、什么时间、有什么 |
| 动作 | 主体 + 动作 + 轨迹，一句话 |
| 过渡描述 | 主体外观、运动轨迹、状态变化、始终存在的东西，四样都写 |
| 目标时长 | 3–10 秒（生成视频建议 2–5 秒） |
| 运镜 | 固定/摇/俯仰/推拉/变焦/升降/环绕/手持，或组合 |
| 首帧构图 | 景别 + 角度 + 构图（如"中景，平视，主体在左三分之一"） |
| 镜间边界 | 连续（接上一镜尾帧）或切 |
| 首帧复用 | 是/否；是时取上一镜实际产出的最后一帧 |
| 对白 | 「角色：台词」，无则写无；画面内开口改画外或字幕 |
| 音效 | 声源 |
| 配乐线索 | 情绪、编配密度、明暗 |
| 旁白预算 | 这段旁白覆盖的镜头总秒数 |

### 6.2 十三列分镜表（交付格式）

镜号 ｜ 画面 ｜ 时长 ｜ 镜头（焦段+角度）｜ 景别 ｜ 内容 ｜ 台词 ｜ 镜头运动 ｜ 画面描述 ｜ 人物站位（俯视图）｜ 音效 ｜ 衔接 ｜ 备注

- 时长独立成列，写成 `3s（0:00-0:03）`。
- 台词标注 `(OS)/(VO)`，无台词写 `[无台词]`。
- 衔接禁止写"自然衔接/继续推进"，必须写动作、视线、声音、道具或光线的具体承接。
- 空间敏感/多人/对峙镜必须有俯视站位图（角色站位+朝向+走位、机位+视锥、180° 轴线）。

### 6.3 镜头语言规则

1. **调度先于景别**：先定谁占优势、视线方向、出入画方向，再选机位。
2. **对话主力是过肩正反打**，锁 180° 轴线 + 视线匹配，不是"默认跟随特写"。
3. **景别 + 焦段 + 角度都要有理由**：广角压迫、长焦隔离、标准自然；俯仰写权力关系。
4. **运镜绑动作或心理**，不作为装饰；"慢"用动作减少 + 凝视 + 缓推 + 长保持。
5. **镜尾要有客观可承接的状态**（`exitState`：姿态、站位、持物、伤况、光线、声场）。
6. **单镜 2–8 秒**，情绪/对话镜默认中近景。

### 6.4 运镜的物理一致性

| 运镜 | 必须满足 |
| --- | --- |
| 摇、俯仰、变焦 | 机位不动，只能看到原地转动或拉近拉远能覆盖的内容 |
| 推拉、跟拍、升降 | 机位移动，路线在场景里真实可走，距离在时长内走得完 |
| 环绕 | 主体全程在画面中间，四周有绕行空间 |
| 手持 | 同推拉，允许不规则晃动 |
| 静态图/代码画面 | 只能是缩放与平移，不超原图分辨率与边缘；大范围运动先出更大的图 |

### 6.5 运镜实现阶梯

| 手段 | 成本 | 控制力 | 说明 |
| --- | --- | --- | --- |
| 提示词运镜词 | 最低 | 弱 | "缓推/横移/环绕"等，模型自由发挥 |
| 首尾帧 | 中 | 中 | 给起点与终点构图，模型补中间 |
| 2.5D 视差 | 低 | 强 | 前景/中景/背景分层，不同速率平移 + 小幅推拉 |
| 3D 预演 | 中高 | 最强 | 先摆机位、焦距、走位，截帧/录制后作为生成参考 |
| 相机参数接口 | 中 | 强 | 如 Kling Camera Control 的水平/垂直移动、pan、tilt、roll、zoom 六参数 |

## 7. 素材与一致性

### 7.1 角色资产

- 三视图（正面/侧面/背面）或四视图（加四分之三），再加表情、年龄、服装状态变体。
- 每个角色一条"角色圣经"：固定外貌段落（逐字复用）、参考图集、固定种子与模型、音色。
- 提示词模板里**不放变量**，变量只进分镜表，保证可复现。

### 7.2 场景、道具与空间

- 场景要有地点 + 时间 + 天气/环境状态，重复场景做多角度参考图。
- 关键道具单独建参考图；空间敏感镜头用俯视站位图锁轴线。
- 进阶：360° 全景、3D 高斯片场（DramaClaw）、场景状态变体，用来锁空间结构。

### 7.3 模型层手段

LoRA（角色/画风）、IP-Adapter / FaceID（参考图注入）、ControlNet（构图/姿态）、固定采样参数与种子。没有训练条件时，"参考图 + 固定描述 + 首帧图生视频"是最低成本的稳定组合。

### 7.4 风格

- 风格模板：上传参考图 → 解析风格参数 → 一键应用到整部项目（DramaClaw 内置 45 种漫剧风格）。
- 风格要写进全局设定，不要逐镜重复描述；逐镜只写差异。

### 7.5 资产库与版本

角色、场景、道具、声线按用途和文件夹管理，跨集复用；每个资产保留版本，"重新生成"不覆盖旧版本。这是"改一处全剧同步"和"回滚到上一版"的前提。

## 8. 视频生成与合成

### 8.1 首尾帧是主流

给起始帧与结束帧，模型插值补运动，比纯文生视频可控得多。ai-comic-studio 用"三层决策"（确定性规则 → LLM 语义判断 → 安全兜底）决定每镜生成首尾帧还是仅首帧。

### 8.2 镜头衔接

- 手动承接：把上一镜真实产出的最后一帧直接作为下一镜首帧（ai-comic-studio 的按钮式做法）。
- 状态承接：在 prompt 里写 `exitState`，下一镜继承姿态、持物、光线、声场。
- 快切：同一动作拆成 1–3 秒的多个内部镜头，靠剪辑节奏而非长镜头运动。

### 8.3 失败模式与对策

| 失败 | 原因 | 对策 |
| --- | --- | --- |
| 崩脸/崩手 | 动作幅度大、参考不足 | 减动作、短镜头、多参考图、口型特写替代全身说话 |
| 画风漂移 | 提示词每次重写 | 固定模板 + 全局风格 + 固定模型/种子 |
| 时长漂移 | 运镜/动作超出模型能力 | 单镜 2–5 秒、拆镜、首尾帧约束 |
| 越轴/空间错乱 | 缺站位与轴线 | 俯视站位图 + 连续性锁 |
| 重复扣费 | 重试无幂等 | 任务身份 + 供应商任务 ID + 内容哈希 |

### 8.4 合成与导出

- ffmpeg 拼接、字幕烧录（ASS/libass）、响度归一（如统一到 −16 LUFS）、限幅。
- 更专业的做法是导出**剪映草稿**：剪辑时间线、转场、旁白轨、字幕轨、BGM 轨全部映射，交给人做最后一公里精修。ArcReel 的实现覆盖了 5.x（`draft_content.json`）与 6+（`draft_info.json`）。
- 导出可编辑工程，比只给 mp4 更有交付价值。

### 8.5 成本

视频按秒计费是主要变动成本。Toonflow 公开案例：2 分钟片、模型费约 ¥130，其中视频约 ¥120、语言约 ¥10、图片不足 ¥1。成本控制的关键不是压单价，而是**降低返工率**。

## 9. 配音与口型

### 9.1 开源方案对比

| 方案 | 能力 | 适合 |
| --- | --- | --- |
| [IndexTTS-2.5](https://github.com/index-tts/index-tts) | 零样本克隆、8 维情绪向量、参考音频情绪、文本情绪、`duration_factor` 语速 0.5–2.0、拼音/音素纠音、中英日西阿 | 中文漫剧主力，情绪与时长可控 |
| [CosyVoice 3](https://github.com/FunAudioLLM/CosyVoice) | 9 语言 + 18 种方言、instruct 指令控制、流式 150ms、发音修补 | 多语言/出海、方言、低延迟 |
| [GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS) | 少样本克隆、本地部署 | 有授权音色、完全本地 |
| [F5-TTS](https://github.com/SWivid/F5-TTS) / [Fish-Speech](https://github.com/fishaudio/fish-speech) | 开源 TTS，质量与生态活跃 | 备选/对比评测 |

注意授权：IndexTTS 使用 bilibili 模型许可协议，商用前需确认条款。

### 9.2 流程

1. 角色绑定音色并写入资产库，跨集不换。
2. 逐句生成，量实际时长，回填分镜 `duration`。
3. 旁白与对白分开处理，音色不混。
4. 字幕按配音时长分布；旁白允许比画面长，但字幕要跟旁白。
5. 统一响度、加 BGM 淡入淡出、限幅。

### 9.3 口型

- 唇形同步模型：[LatentSync](https://github.com/bytedance/LatentSync)、[MuseTalk](https://github.com/TMElyralab/MuseTalk)。
- 更稳的做法：**口型特写 + 轻微头部动作**，避免全身说话；漫剧可以用分镜、空镜、反应镜头绕过口型难题。
- 说话人绑定：画面有多张正脸时，口型容易落到错的人脸上；分镜要写明谁说话、其他人闭嘴或出画。

## 10. 监控与干预

### 10.1 任务模型

一条生成任务至少要有：任务 ID、目标对象（项目/集/镜头）、供应商与模型、请求参数、内容哈希、供应商任务 ID、状态、尝试次数、费用、错误、时间戳。持久化到数据库，进程重启不丢。

### 10.2 状态机

```text
pending ─► queued ─► running ─► succeeded
                        │  ├─► failed（可重试）
                        │  ├─► timeout
                        │  └─► interrupted（进程中断，重启恢复）
                        └─► orphaned_provider_job（有远程任务 ID 但本地未完成）
queued ─► cancelled（只能取消排队中的任务）
```

### 10.3 幂等与恢复

- 内容哈希命名：`shot_id + hash(prompt + model + params)`，已存在则跳过，改提示词自然生成新文件。
- 提交前查重，提交后立刻落供应商任务 ID。
- 中断后先 `audit` 再 `collect`，能取回就取回，确认终态失败才重投。
- 只允许取消排队任务；执行中的调用照常跑完并成为产物。

### 10.4 闸门与预览

- 生成前返回"本次准确的数量、内容、参考、参数、输出与费用"，用户确认后才调用付费接口。
- ArcReel 的 `preview: true` 不入队、不扣费，返回逐镜头去向与报价；正式提交带上确认过的时长档位。
- 批量模式下可配置自动放行规则（如参考图齐全、时长合规、预估费用低于阈值），其余仍走人工确认。

### 10.5 自动质检

- ffmpeg 本地信号：`blackdetect` 黑屏、`freezedetect` 卡帧、`scene` 切点打分，生成联系表（最多 12 帧/单元）。
- 审图/审片做成**只读子代理**：只出报告，不改文件、不触发生成，是否重做由人决定。
- 检查器校验文档间的引用与时长一致性（drama-skills 的 `creator_markdown_check.py` 会指出"分镜 2 秒 vs 视频提示词 3 秒"）。

### 10.6 版本

资产版本、分镜版本、剪辑时间线修订都要保留。剪辑时间线用 `base_revision` 做乐观并发，冲突时拒绝而不是覆盖。

### 10.7 成本

按调用上报用量（token、秒、张数），完成时冻结费用，价目表变化不重算历史。按项目/集/镜头聚合，才能定位"哪一集在烧钱"。

## 11. 批量生产

### 11.1 四个指标

| 指标 | 含义 | 观测方式 |
| --- | --- | --- |
| 并发渲染 | 一天能出几集 | 队列吞吐、排队时长 |
| 资产库 | 角色/场景跨集复用率 | 复用资产占比、改一处同步范围 |
| 合格率 | 分镜一次通过率、角色崩坏率、返工率 | 人工抽检 + 自动信号 |
| 单片成本 | 视频秒数 + 图片 + 配音 + 返工 + 人力 | 用量表按项目聚合 |

### 11.2 三种架构

1. **自建**：ComfyUI + FFmpeg + 编排器，资产自持、边际成本低，但要养技术团队，口型、审片、项目管理要自己补。
2. **托管工厂**：Catimind、万兴剧厂、知漫剧、360 纳米等，开箱并发、资产库、协作，代价是平台锁定与积分计费。
3. **混合**：自建或工厂保吞吐，前端用 3D 预演锁镜头，少量人工质检兜底。

### 11.3 可复用机制

- 模板/配方：把"某一类片子"的阶段组合与参数固化成可复用单元。
- 批量清单：JSON/JSONL 跑批，支持断点续跑与失败重试。
- 资产复用：角色卡/场景卡跨集共享，改一处全剧同步。
- 前置预演：把调度错误拦在批量之前，避免"一个错误 × 几十集"。
- 队列分通道：图片、视频、音频、渲染各自并发，互不阻塞。

### 11.4 批量经济学

先测准合格率，再谈并发。用自己剧本各跑一小批，用实测合格率反推单片成本；宣传的通过率、单集耗时、单价口径不一，不宜直接采用。

- 后续里程碑与未决问题：设计文档 §9–§10。

### 12.1 保留的产品红线

无论后续怎样迭代，以下五条来自研究结论的红线不变：

- 不做"一键生成整集"的入口，它只会放大失败。
- 不让 LLM 每次自由写视频提示词；提示词由分镜字段与已确认资产确定性编译。
- 不在资产未冻结时批量生成。
- 不把"重新生成"实现成覆盖原文件；旧版本必须可回溯。
- 不在没有幂等与任务持久化之前开放批量。

### 12.2 对当前实现的提醒

- 研究中的成本、通过率与耗时均为作者自述，不能当作星晴的验收指标；需要用本项目剧本小批实测。
- 视频/图像/TTS/合成尚未实现，界面不得用"已支持"的文案暗示能力。
- 分镜产物目前是运行产物，不是可编辑的 `shots` 表；在落库前，不能用它承诺逐镜版本管理。


## 13. 风险与未决问题

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 许可证污染 | AGPL/Elastic 代码进入闭源产品 | 只读设计，独立实现 |
| 供应商漂移 | API、参数、计费变化 | 适配器 + 能力描述 + 价目快照 |
| 一致性上限 | 模型对跨镜身份的控制有限 | 资产冻结 + 参考图 + 首帧复用 + 人工抽检 |
| 成本失控 | 批量重试与返工 | 预算上限 + 幂等 + 预览报价 |
| 合规 | AI 生成标识、版权、平台规则 | 发布前检查清单 + 水印/标识 |
| 剪映格式不稳定 | 草稿结构随版本变化 | 固定版本适配 + 降级导出 mp4 |

未决问题：

1. 静态漫剧的视差分层由人工拆还是模型自动拆？需要素材管线验证。
2. 分镜由 LLM 生成后，导演审镜能否规则化到可自动拦截的程度？
3. 批量模式下自动放行的安全阈值怎么定，才能既不误放又不拖慢？
4. 剪映草稿导出是否值得投入，取决于目标用户是否真的二次精修。

## 附录 B：生成前检查清单

1. 分镜总时长是否超集时长预算；单镜是否超 5 秒（生成视频是否超 8 秒）。
2. 镜号是否唯一；台词是否标注说话人与 OS/VO。
3. 每个角色是否有可复用的参考资产；跨集造型是否挂连续性锁。
4. 空间敏感镜头是否有人物站位/轴线说明。
