# 炼丹炉：原生内容工作台

## 方向与边界

面向需要从既有视觉素材提炼、配比、回看并导出设计简报的人。首要对象是**素材图像与可追溯规格**，不是统计指标。沿用项目 Rust / Iced 0.14 原生渲染，不切换 SwiftUI，不引入 WebView、Node 或 HTTP 服务。

自主选择「安静的素材工作台」：单层侧栏、顶部搜索与任务操作、中央真实图像集合 / 对象列表、右侧可收起检查器。近白与石墨承担结构，素材自身承担色彩；温和琥珀只用于当前主操作。唯一强化细节是与真实数据绑定的「选材 → 药液 → 配方」合成轨迹，以及配色 / 间距比例。

排除另两方向：

- **仪表盘 / 实验监控台**：大数字、装饰三卡会把注意力从选材与图像证据转移到指标；数量只在侧栏与列表头作为辅助上下文。
- **编辑杂志 / 炼金术戏剧化**：大衬线标题、霓虹、渐变和仪式性插画会占据视觉判断空间，并容易暗示本地像素计算拥有模型或审美能力。

这不是把通用模板换成「炼丹」文案：合成轨迹指向当前素材、当前药液版本和用户比例；真实 A/B 图缺失时，视觉评审不可提交，不用文字检查分代替。

## 真实操作与数据保护

- **素材库**：读取 snapshot 中的素材、标题、领域、集合、真实 image_path 与药液数量；搜索即时过滤，图网格 / 对象列表可切，24 项分页可浏览返回的全部记录。图像在后台解码为 720px 范围预览并缓存，缺失 / 解码错误不拿假图补位。
- **炼丹台**：当前素材预览、当前药液与历史版本、实际保存的颜色样本；本地炼药只运行 palette + spacing 像素计算，明确不推断语义、不请求模型。像素配方的配色比例与互补间距比例绑定真实 `BrewLocal`；选择本地 JSON 配方调用 `BrewRecipe`。没有文件路径的数据库内置配方可浏览但不冒充可执行文件。
- **丹药**：真实对象列表，选择后显示冻结规格、创建 / 配方信息与检查状态；仅存在冻结规格且数据库已解锁时才可导出 Brief。原生目录选择器明确选择导出父目录，后端在其中新建独占子目录并输出 Brief 与 token 文件；成功状态展示返回的实际 out_dir，不把目录伪装成单一 Markdown 文件。结构或文字检查明确不等于视觉质量。
- **我的偏好**：只显示已有匿名 A/B 本地图像；图像与 manifest 未就绪时禁提交，四动作为 A / B / tie / abstain，提交前显示来源与私有意图供确认。没有可评实验时提供刷新 CTA，而不是把文字分当视觉证据。
- **身份边界**：`effective_demo = --demo || snapshot.demo`。demo 永远发送 `demo=true, person=None, personal=false`；不会伪造真人。正常模式不填 person 时不记 human，并禁用提交；已有 person 可由人明确点选，不自动猜身份。`我的私人偏好` 默认关闭，仅人明确填身份并主动开启后才传 `personal=true`。页面展示 raw / usable / status / active 与冷启动说明，不自动拟合或激活个人内核。
- **原库保护**：启动或打开已有 DB 一律只读，不迁移、不默认创建用户库。写动作要求使用真实系统另存为建立工作副本，或显式建立新库；成功切换目标后才打开前端写门，后端继续验证 current schema。目标已存在时由后端原子拒绝覆盖。取消对话框不变更库。
- **后台与竞态**：snapshot、图像解码、执行动作、文件对话框与 PNG 编码均通过 `tokio::spawn_blocking` + Iced `Task`；数据库动作全局串行，忙碌时禁写，但仍可浏览当前数据。结果同时核对 generation 与来源配置（图像核对 generation），旧结果不能覆盖切库后的数据。
- **原生截图**：`--screenshot PATH.png [--exit-after-capture]` 等待数据与图像就绪，并观察实际窗口渲染帧与稳定 tick，随后用当前 window ID 调 Iced compositor screenshot；PNG 使用 create_new，不覆盖任何已有文件 / 链接，不调用 OS 屏幕录制、不启动 Web。
- **启动**：`--db PATH --root DIR --recipes DIR`；不传 DB 时进入安全空状态，不读取默认真实 data；`--demo` 必须明确指定隔离库；`--screen library|brew|pills|preferences` 与 `--window-size 1280x860` 可供真实窗口验收。

## 验证与限制

实现者验证结果（本机 macOS，2026-11-12）：

- `cargo check --locked --offline ... -p ie-desktop` 成功。
- `cargo clippy --locked --offline ... -p ie-desktop --all-targets --no-deps -- -D warnings` 成功，无此 crate 警告。
- `cargo test --locked --offline ... -p ie-desktop`：**30 passed, 0 failed**；覆盖旧配置 / generation 拒绝、启动写锁、demo / 身份 / 私人意图、搜索对象一致性、素材根重新打开、冻结摘要、原始数据折叠和桥接失败的真实反馈等。全 workspace 集成为 172 项通过，见[界面验收](炼丹炉可视化界面验收.md)。
- `cargo build --locked --offline ... -p ie-desktop` 成功，开发二进制位于 `/tmp/ie-studio-target/debug/ie-desktop`。
- 仅 `cargo fmt --manifest-path inspiration/Cargo.toml --package ie-desktop` 及同范围 `-- --check`，最终成功；没有运行 workspace 全量格式化。
- 构建使用父代理约定 `CARGO_HOME=/tmp/cargo-home CARGO_TARGET_DIR=/tmp/ie-studio-target CARGO_BUILD_JOBS=2`，依赖 / lock 由父管理。

初版编写阶段仅做单 crate 检查，不把构建成功当视觉验收。随后集成阶段已实际启动原生窗口、read_image 查看浅色 / 紧凑深色与工作流画面、修正实质问题、完成隔离端到端回归和本地签名 .app 打包，记录见[界面验收](炼丹炉可视化界面验收.md)。没有编造审美评分、把演示当真人或发起付费模型调用。

Iced 的跨平台窗口 / 控件不是 AppKit 原生控件：本版保留系统窗口边框与系统文件对话框，但没有自定义完整 macOS 应用菜单、NSColor/Increase Contrast 桥接或经 VoiceOver 验证的辅助功能树。Tab 使用 Iced focus operation 遍历可聚焦输入；不能声称全部按钮都有完整键盘焦点。Cmd/Ctrl 快捷键与 Escape 已实现。未实测项由父验收记录，不能以代码推断通过。
