# 炼丹炉个人闭环 · 第三阶段验收

> 2026-11-12。承接[可信基础](炼丹炉可信基础验收.md)与[成品回流](炼丹炉成品回流验收.md)。三阶段研究代码链路已接通；这不是稳定个人审美、跨领域内核或正式桌面产品的完成声明。

## 1. 已实现的链路

明确本机个人用途 → 本人真实选择 → private judgment → 最终截图自身的冻结特征 → 受控拟合/验证 → 显式试用 → 已渲染配方候选排序 → 原药液钉住的新丹药及选择轨迹。

实现：[个人证据](../../inspiration/crates/ie/src/personal.rs)、[拟合与排序](../../inspiration/crates/ie/src/fit.rs)、[炼丹接线](../../inspiration/crates/ie/src/alchemy.rs)、[隐私导出](../../inspiration/crates/ie/src/bundle.rs)、[schema 25 迁移](inspiration/migrations/024-personal-evidence.sql)。命令见[CLI 说明](../../inspiration/README.md)。

### 真实来源与身份边界

- `person init` 只建立明确的 local-only 个人用途声明，不作身份认证；已有 demo 或用途不明确的旧身份不升格为真人。
- `experiment record` 须明确 `source=human`、reviewer 与 person 一致、`intent=personal_preference`。普通视觉审稿不是自动的个人偏好训练标签。
- 旧 judgment 和 kernel 保留原值，来源默认 legacy；simulate 新记录明确 demo，仅独立演练身份使用。真人身份不能用于演练，演练也不能替换真人 active 内核。
- 视觉记录与个人桥接分开。桥接失败会明确保留视觉记录并说明未创建个人判定；重试幂等，不把一次选择重复凑样本。

### 截图特征与去重

- 每个最终 artifact 建独立 private generated work 和实际截图 asset，不复用原药材 work/向量。
- 从最终 PNG 只取现有较可信的留白与细节密度像素代理，冻结特征、hash、scope、契约与完整证据；空白/缺特征保持缺失，不补零，不将配方 ID、A/B 或赢家注入特征。
- 规范化页面/截图对，按原评价顺序取最新，再排除 tie、abstain、零差和无共同可信特征。倒序展示、迟桥接旧票或重复评价不增加可用样本。
- 后续 live 向量 upsert、语料增加和演练不会改写已冻结训练特征。

### 冷启动、验证与使用

- 少于 10 个可用对：不拟合、不写新模型、不替换旧 active。
- 10 起：仅 L0 草稿；达到 20 也不自动启用。
- 工程试用资格还要求至少 5 个独立内容组、10 个训练对/3 个训练组、8 个分组留出对，优于训练常数基线且 95% Wilson 下界高于 0.5。normalizer 仅来自训练组，保存 mean/std、词表/掩码、分组、参数、训练证据与哈希。
- 只有明确 `--activate` 且验证合格才设置 human active；验证失败、少量草稿或事务异常不替换旧内核。active 仍只代表受限试用，不证明成熟或跨域稳定审美。
- 排序还需 active human、匹配 scope/特征契约、当前证据完整、候选同条件以及显式 `--apply-personal`。其余保持原序；证据损坏不炼制未核验快照。
- 新丹药使用所选成品参照的完整冻结配方和原药液 ID，核对内容/版本/revision/hash/输入身份，冻结个人选择 trace；不自动调整每味药质量，不用个人化绕过硬约束。

## 2. 隐私与兼容

默认公开语料导出排除 private generated work、相关素材与其证据引用。显式个人导出/导入保留 visibility，不能把 private 静默变 public；不支持私有标记的旧库拒绝私有导入并回滚，而非降级隐私。

语料包仍不是完整个人备份：没有传输 judgment/session、实验/成品/评价/特征与内核之间的完整证据图，不恢复个人训练状态。完整本地留存应使用 SQLite 一致性备份。

身份、具体选择、个人特征和实际数据库不提交仓库。本机 local/private 是用途与导出边界，不是加密、远程鉴权或抗数据库所有者篡改的签名。公开的第二阶段样例证据是生成当时的演示快照，不随本机后续私人样本更新。

## 3. 验证证据

独立 workspace 实际通过 **112 个单元/模块行为测试 + 11 个 CLI 集成测试，合计 123 个**，并通过：

```sh
cargo fmt --all -- --check
cargo test --workspace --all-targets --locked --offline
cargo clippy --workspace --all-targets --locked --offline -- -D warnings
cargo build --release --locked --offline
```

回归测试的 human 标签和可信 Chrome 资格均为明确隔离的 synthetic fixture 声明，数据在临时目录，不冒充真实用户采集数量，也不调用真实模型。关键回归：

1. 200 条 demo 混入仅一次明确真人选择，真实样本仍为一次，保持冷启动、不启用；身份、来源、用途、mock 或证据不符不能桥接。
2. 反向展示映射、幂等修复、迟桥接旧票、最新 tie/abstain、零特征差与空白缺失处理正确。
3. 9 对不拟合、10 对只 draft；分组无泄漏，改 holdout 不改 train normalizer/权重，新增语料/演练/live 向量不改旧内核尺度或完整排序输出。
4. 明确 synthetic、仅临时目录的 24 个独立内容/PNG/回执 fixture，经生产 `personal::record → fit_person(activate) → rank(apply)` 可改变候选序；不可信、未开启或证据坏时回退原序。
5. 验证失败、少量草稿与 INSERT 故障不覆盖旧 active；个人炼丹不允许替代缺失药液或强行绕过硬约束，旧丹药不漂移。
6. 私有作品默认不公开；显式导出/导入往返仍 private；CLI 冷启动可观察，个人模式不能被静默忽略，`--activate false` 不会误当同意。

发布版 CLI 另在明确授权的本机私有数据上验证了采集、幂等桥接、冷启动、选择轨迹与公开导出排除。具体个人数据不写本报告；此核验没有把少量选择包装为已拟合或已启用。原始默认用户库内容哈希未变，迁移与新增只在独立本地库完成。没有调用付费或真实生成模型。

## 4. 仍需后续验证

- 当前个人特征只覆盖 UI 静态截图的两个像素代理，不代表完整美学内核、跨域一致性或单条偏好的因果解释。
- 试用门槛是保守工程门控，不是稳定性的统计保证；需要更多独立真实样本与长期验证，不能靠 simulate 补足。
- 未验证真实交互、动效、视频、Windows/Linux 和远端 CI；星晴根 workspace 的并行改动不在本轮提交和验证范围。
- 本阶段只使合格内核能够影响已有成品参照的配方选择，不外推未生成的配方，不自动学习药液之间的因果贡献或改配比。
