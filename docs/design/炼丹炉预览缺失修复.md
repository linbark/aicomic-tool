# 炼丹炉 0.1.1：真实素材库预览修复

> 2026-11-13。修复用户反馈“很多素材没有预览图”。这次验证使用真实素材库的只读查询和实际原生窗口，不再仅依赖带扩展名的演示图。

## 复现与根因

原库有 865 条作品记录、851 条本地图像记录：827 张 WebP、24 张 JPEG，全部存为 `blobs/<前缀>/<内容哈希>`，文件名没有扩展名。文件实际存在。

旧版本在 [studio 预览查询](../../inspiration/crates/ie/src/studio.rs)中用 `image::image_dimensions(path)` 预筛选；这个 API 默认从扩展名确定格式。它把无扩展名的有效图像筛成 null，前端连加载机会都没有。前端解码器本来使用内容签名识别，两端输入契约不一致。

通过公开 `studio::snapshot` 在真实原库复现：**865 条作品、0 张可预览**；随后用临时库无扩展名图像建立同样失败的公开接口回归。先观察失败，再修复；没有改路径、重命名图片或改写用户数据库。

初版只用 `.png` 演示图检查渲染，漏测了实际哈希素材仓库。这是本次应补上的验收缺口，不是把缺图归因给用户。

## 修复

- 后端轻量探测改为 `ImageReader::open → with_guessed_format → into_dimensions`，与前端解码器按文件内容识别的规则一致。无扩展名、扩展名与内容不符的有效 JPEG/WebP/PNG 均可预览；非图像仍拒绝。
- 素材返回明确的预览状态：可用、未关联本地图像、文件不在当前目录、无法读取或格式不支持。界面不生成假预览，不把真实缺失显示为无限加载。
- 显式刷新会重新探测失败缓存和已成功缓存；文件在相同路径修复后可以重试。忙碌不乱清缓存，旧 generation 结果仍拒绝；读取刷新失败时保留错误说明，并重排上一成功快照的可见图片。
- 增加原生“选择素材目录…”与当前目录显示。用于旧副本缺根目录提示、素材移动等情况；用户明确选择后优先采用新目录，不更换 DB、不自动解除只读、不写用户库、不猜测或扫描其他目录。
- 发布版本升为 0.1.1，窗口标题显示版本，避免把旧的运行窗口误当作已更新。

## 真实数据核验

[只读审计工具](../../inspiration/crates/ie/examples/preview_audit.rs)通过与 GUI 相同的公开查询边界运行；`--decode` 再按实际内容完整解码每张可用图片。只输出汇总，不输出个人身份、偏好、模型参数或图片内容。

从仓库根目录执行：

```sh
cargo run --release --manifest-path inspiration/Cargo.toml -p ie --example preview_audit -- \
  --db data/inspiration/inspiration.db --root data/inspiration --decode
```

修复后实际结果：

```json
{
  "works_audited": 865,
  "preview_available": 851,
  "without_preview": 14,
  "preview_status": { "available": 851, "no_local_asset": 14 },
  "full_decode": { "decoded": 851, "failed": 0 },
  "source_database_unchanged": true,
  "network_or_model_requested": false
}
```

剩余 14 条是数据库尚未关联本地图像的记录，不宣称已经补图。没有自动下载、伪造图像或把演示图冒充原素材。
