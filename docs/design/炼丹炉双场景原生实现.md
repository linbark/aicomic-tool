# 炼丹炉：双场景原生改造

> 2026-11-13 · 0.2.0。用户已在游戏式 v2 演示后明确授权“开始改造”。本文记录原生实现、验证和仍未验证的边界；网页原型不作为原生交付或真实模型效果的证据。

## 1. 两个主界面

- **藏经阁**：管理手法、配方、丹方；编辑 Prompt、输入/输出契约、配比、约束、DAG 引用，追加保存版本，历史版本恢复为草稿。
- **工坊**：取用明确保存的版本，组装节点与主/支依赖，选择素材或输入文字，配置本地模型，启动真实任务并审阅进度、错误与产物。
- 藏经阁不显示运行棋盘和开炉配置；工坊只展示绑定版本的只读摘要，需要编辑时跳到藏经阁。导航只导航，切页保留草稿/筛选/选择；保存新版不能偷偷改变已装配节点。
- 原有素材库、丹药规格、Brief 导出与匿名成品/私人偏好仍保留资料入口，不因界面改造丢失。

视觉沿用已确认的墨绿工作台、旧铜主操作和纸卷编辑面。正式界面使用 Rust/Iced 原生控件及功能性画布，工坊背景为随程序打包的生成美术资产；不嵌入 HTML/WebView，不引入 Node/Python 或 GUI HTTP 服务器。

## 2. 持久化与版本

[后端边界](../../inspiration/crates/ie/src/atelier.rs)提供独立的 Prompt 资产与运行日志，迁移到 schema 26。手法是 Prompt 与契约，配方包含结构化比例及合成 Prompt，丹方是节点引用与输入依赖，不是另一个大 Prompt。

资产键和类别形成身份；保存追加不可变 revision，内容 hash 在读取和运行前核验。丹方引用明确的版本，运行开始前冻结节点、引用内容、源输入与模型参数。旧版本和既有炼丹/评价/个人证据的语义不被重写。

原库及现有工作库启动/打开仍只读。升级只发生在用户明确创建的新工作副本或新库；不靠浏览、模型探测或界面初始化隐式迁移。新增的 starter 是可编辑的 Prompt 模板，不冒充已生成作品、实际模型结果或真人偏好。

## 3. 执行语义

首轮支持可解析的 `source → technique / recipe → export` DAG。运行前拒绝悬空或重复节点、循环、缺失版本、无效契约、非法比例和不匹配的配方输入；按依赖执行，失败阻止下游。

- Prompt 节点经真实本地 HTTP 模型客户端处理，不由 UI 随机产生输出或进度。
- recipe 的相对权重归一化，声明值与有效值一起冻结，可复查。
- 图像按内容识别，兼容无扩展名哈希文件；必须明确启用视觉输入，不静默向文本模型发图。
- JSON/契约失败是失败，不编造合格结果。产物只做数据与 Brief 导出，不执行模型生成的命令或脚本。
- 运行和 stage 记录真实状态、输入/输出及错误。UI 使用后台任务和带配置/代数/运行身份的事件，旧结果不得覆盖新工作库。
- 停止至少阻止后续请求和结果提交；阻塞中的 HTTP 可能要等响应或超时，界面应显示“已请求停止”，不虚报即时中断。
- 产物位于工作 DB 父目录下新建、唯一的运行目录，不能覆盖已有文件或链接；不得把原素材目录当作默认写入目录。

## 4. 本地模型与信任边界

支持 Ollama 和 OpenAI 兼容的**本机**端点。客户端限制 loopback/localhost，拒绝云端、非本机地址、userinfo、fragment、重定向及环境代理；不继承云端密钥、不隐式回退云端、不下载模型。启动不自动发起推理；发现服务与模型和运行任务分别有明确操作。

Ollama 的 context 映射到 `num_ctx`；标准 OpenAI 兼容接口不能通用地设置服务端模型上下文，因此该配置必须注明记录/预算语义，不能假装已改服务器上下文。

本次初始只读探测 `127.0.0.1:11434/api/tags` 返回 connection refused：表示当时服务未响应，不等于模型不存在或调用失败。自动验证使用隔离 loopback HTTP 模拟服务；若未实际运行已安装模型，最终验收应明确披露，不把 mock 当作真实推理。

模型输出不创建人类选择、私人画像或学习证据，不自动拟合/激活内核，也不使用模型自评分冒充审美评价。

## 5. 验收目标

- 公开接口 RED→GREEN：追加版本、不可变/篡改检查、DAG 与配方校验、只读源库不变、参数/输入冻结、真实请求与失败/取消、导出不覆盖。
- 原生公开 update 回归：主页面隔离、草稿保持、显式绑定版本、过期保存/模型/运行结果、只读权限、停止与切库安全。
- [隔离验收工具](../../inspiration/crates/ie/examples/atelier_acceptance.rs)使用全新指定目录和真实 loopback HTTP mock，验证文本及无扩展名图像的完整链路；不访问默认用户库，不生成真人样本。
- 独立 workspace 的 fmt、全部 target 测试、clippy `-D warnings`、locked/offline release 构建。
- 实际原生窗口截图检查两个主页面与紧凑尺寸；发布包核验。不得以网页演示图代替原生截图，不把 Mac 验证冒充 Windows 验证。
- 提交前只收源码、迁移、静态界面美术和文档；用户数据、设置、模型权重、运行产物、截图和发布包不提交。

## 6. 0.2.0 实际验收

### 自动与 HTTP 链路

在独立 workspace 执行 fmt、全部 targets 测试、strict clippy `-D warnings`、locked/offline release 构建，全部通过：**219 tests = 150 引擎/Studio + 11 CLI + 58 原生状态回归**。原有 183 项保留，没有删除来源、只读、私人证据或预览保护断言。

[完整链路验收工具](<../../inspiration/crates/ie/examples/atelier_acceptance.rs>)分别用 `--protocol ollama` 与 `--protocol openai` 在全新临时目录执行：每个协议完成文本、无扩展名 PNG 两个五节点 DAG；合计 **4 runs / 12 次实际 loopback HTTP 请求 / 4 次携带真实图像字节的请求 / 48 条事件**。生成的 JSON、Brief 与持久记录可读；两库均 `person=0`。这是有标记的 HTTP mock 验收，**不是实际模型推理**。

有界独立 review 发现并修复“丹方首次保存失败后，同 key 修正装配仍不能重试”：只允许替换未经用户继续编辑的工坊派生草稿，保留藏经阁手工编辑和旧请求防线；新增3项公开 update 回归，实际 RED→GREEN。

### 原生窗口与截图时序

已实际运行并检查 1440×900、1040×720 的藏经阁和工坊。工坊棋盘可双向滚动，紧凑窗口仍可取用/选择全部节点；纸面字段与历史内容可滚动访问。编辑框正文、纸面次级字、墨绿面板次级字与主操作的源码色值对比度分别约 **10.53 / 5.18 / 7.23 / 6.23:1**；状态同时用文字表达，不只靠颜色。未执行 VoiceOver、大字体系统设置或 Windows 原生验收。

### 现有数据保护

用正式 `studio::snapshot` 边界只读审计并完整解码：原库 schema21，865条作品中851张本地图像全部成功；现有用户工作库 schema25，**853条 / 853张全部成功，无缺图**。两个文件与本轮改造前 SHA-256 基线完全一致；没有迁移、删除、重新标注或发起模型请求，也没有触碰用户偏好。

### 发行与限制

最终发行目录为 [macos-arm64-0.2.0-final](<../../inspiration/dist/macos-arm64-0.2.0-final/>)，Apple Silicon Mac，本地 ad-hoc 签名；不是 Developer ID 公证发行，不声称 Windows 已验证。模型服务初始和收尾探测均未响应，因此未做真实权重推理或效果评估。

首用建议：打开应用 → 建立新工作副本/新库 → 在藏经阁修订保存模板 → 工坊明确取用 starter 丹方并确认 → 输入文字或绑定真实素材 → 配置并发现已安装的本机模型 → 开炉 → 审阅实际输出。仅本机无鉴权端点；不会代装模型。来源/版本/JSON 契约不满足时要按错误修正，不能强行当成合格产物。
