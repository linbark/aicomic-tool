# ADR 0001：以主库提交凭据对账素材操作

状态：已采用；全工作区 269 项测试、严格 Clippy 和发布静态自检通过。另有 1 个由父测试显式调用的子进程辅助入口按设计标记 ignored。

## 背景

删除和媒体替换跨越主 SQLite、记忆 SQLite 和文件系统。仅靠析构恢复隔离文件，无法处理进程被终止；临时目录析构还可能清除未恢复的唯一副本。主库使用 WAL 时，不能把 ATTACH 的跨库提交当作所需的崩溃原子性。

## 决策

将恢复实现收在私有[存储操作 Module](../../crates/aicomic-core/src/operations.rs)，保持既有 Store 删除、素材导入和视频替换 Interface。它不是后台任务系统，也不引入服务进程或新运行时。[主库迁移](../../crates/aicomic-core/src/schema.rs)升级到 schema 4，清单使用认证 v2；旧业务 ID、Context 和 Run 格式继续保留，迁移前先备份主库。

1. 在主库 `BEGIN IMMEDIATE` 下规划操作。不可恢复的既有意图必须先处理，不能绕过它继续破坏其对应业务事实。
2. 文件副作用之前，发布包含操作 ID、主库身份和受限相对路径的持久隔离清单。清单原意图使用主库保存的本地认证密钥认证；仅检查“项目存在”“路径有任意 owner”不能证明未提交清单没有把原件重定向给另一个合法项目。密钥不写入清单、日志或错误。文件只移动到本操作私有目录；新媒体先复制到该目录，不覆盖或删除外部源文件。
3. 同一主库事务写业务变更与存储提交凭据。凭据不依赖被删除项目的外键，其存在代表业务已提交，不代表后续清理已完成。
4. [记忆清理](../../crates/aicomic-core/src/memory_cleanup.rs)使用已有记忆库的独立写事务，不创建缺失的记忆库。先收集历史引用高水位并写回主库，再执行真实 DELETE；普通错误发生在主库提交前，回滚整个记忆事务和主事务，并恢复隔离文件。
5. 主库提交后才提交记忆事务，再完成新文件发布和隔离文件清理。不能在持有记忆写事务时反向争抢主库写锁。迟到发布在主库锁下复核引用，不重新发布已被后续操作消费的私有副本。
6. 启动及显式重试依据同一主库的凭据对账：无凭据恢复原路径；有凭据完成清理，不重新执行业务变更。恢复可以再次被终止，下一次仍可继续。
7. 认证、路径、清单版本、数据库身份、文件类型或两端状态不可信时保留现场并报错，不猜测、不覆盖现有文件、不用临时目录析构兜底清除现场。旧的未认证清单只有主库中存在逐字匹配的已提交凭据时才可兼容；无凭据的旧意图不能自动推断原归属。

## 错误与调用方责任

- 提交前普通失败：业务没有提交，恢复旧文件；若恢复也失败，返回带操作 ID 的 `RecoveryRequired`。
- 提交后清理失败：返回 `CommittedPending`，调用方应重新加载真实业务状态并提示待恢复，不误报为整单回滚，不再次导入或重复替换同一业务操作。
- `Store::open` 自动对账；`Store::recover_pending_operations` 可在同一进程重试。[Store 与错误定义](../../crates/aicomic-core/src/lib.rs)是该合同的公开入口。

## 写入活动边界

[项目写入活动租约](../../crates/aicomic-desktop/src/activity.rs)按真实项目归属跟随异步与阻塞任务，最后一个实际写者退出后才静止。取消 UI 等待不等于阻塞任务结束；[任务上下文 Adapter](../../crates/aicomic-desktop/src/task_context.rs)必须把租约放到真正的写任务中。整个 AI 工作流仍可取消，不为了等待写入而让已取消工作流继续启动生成阶段。

桌面端只在项目后台写入静止后接受删除，用户需要再次确认，不自动排队删除。此协议不协调任意旧客户端或外部进程的 ContextStore：同一数据目录仅应有一个应用写者。遇恢复冲突应停止修改、备份整目录并处理保留的现场。

## 验证与限制

- [强杀回归](../../crates/aicomic-core/src/operation_tests.rs)通过握手命中窗口后终止子进程，不用会执行析构的 panic 代替进程终止。
- 保留[存储兼容回归](../../crates/aicomic-core/tests/storage.rs)：普通错误完整回滚、共享素材引用、Windows 相对路径写法、ID 高水位、缺失记忆库和迁移备份。
- 目标是进程中断恢复，不宣称完成物理断电验证。目录同步的平台差异需要保留；Mac 运行结果不是 Windows 本机验收。
- 清单认证保护在可信主库下的原意图完整性，不加密项目内容，也不隔离能修改整个数据目录和主库的恶意本机进程。
- 不扫描和删除所有未引用素材；无清单的旧隔离目录不能自动推断原路径。
