基于《AI漫剧创作全流程系统提示词工程深度研究报告》，梳理了在**剧本创作**环节（从大纲提炼到剧本生成与优化）的核心 System Prompt 策略与指令架构。

这份文档将 Prompt 视为“软件模块”，以下是针对不同阶段的模块化整理：

### 1. 架构师代理：大纲提炼与世界观提取

此阶段的目标是将原本模糊的小说文本转化为结构化的、可视化的“工程蓝图”。

* 
**核心认知架构（Role）：** 定义 AI 为“资深概念艺术家和世界观架构师” 。


* **世界观提取（Series Bible Extraction）：**
* 
**视觉优先原则：** 指令必须要求 AI 忽略角色内心独白，专注于提取物理特征、环境细节和光影氛围 。


* 
**核心标签（Visual DNA）：** 要求生成不可变的角色视觉标签（如 `<visual_dna>银色短发, 赛博义眼</visual_dna>`），用于后续锚定绘图一致性 。


* 
**冲突映射：** 要求分析核心冲突（如自然 vs 科技），并将其定义为具体的视觉隐喻 。




* **大纲结构化（Beat Sheet Generation）：**
* 
**双阶段精炼：** 强制先生成宏观的“故事弧光”，再细化为“场面节拍”，禁止一次性生成详细脚本 。


* 
**结构化输出表格：** 要求输出包含“节拍类型”（激励事件/高潮）、“情感电荷”（+/-）、“视觉重点”和“预估格数”的表格 。





### 2. 编剧代理：剧本生成与格式化

此阶段的目标是生成符合工业标准、可直接用于分镜转化的文本。

* **核心认知架构（Role）：** 定义 AI 需遵循“Fountain 语法”和“展示而非讲述”原则。
* **格式即法律（Strict Syntax）：**
* 
**Fountain 格式强制：** 场景标题全大写（INT./EXT.），角色名居中，严禁使用无关的 Markdown 符号 。


* 
**垂直流动感：** 限制动作描写（Action Blocks）长度不超过 3~4 行，强制 AI 将复杂动作拆解为独立的视觉镜头 。




* **内容约束（Negative Constraints）：**
* 
**反心理描写（Anti-Psychologizing）：** 严禁描写“他感到悲伤”或“他想起童年”。必须通过 System Prompt 强制将心理活动转化为物理动作（如“他摩挲表盖”） 。


* 
**潜台词注入：** 要求角色通过撒谎、回避或反讽来表达意图，禁止直白的对话（On-the-nose） 。


* 
**呼吸原则：** 限制单个气泡文字量（如不超过 30 个汉字/25 个单词），超量需拆分 。





### 3. 大纲与剧本优化：逻辑自检与节奏控制

此阶段利用“元认知”提示词对生成内容进行迭代优化。

* **翻页工程（Page Turn Engineering）：**
* 在 System Prompt 中指示 AI 识别惊奇或揭秘时刻，并强制将其安排在偶数页的最后一格（右下角），驱动读者翻页 。




* **动作原子化（Action Atomization）：**
* 对于“他杀出重围”这类高密度文本，提示词需引导 AI 将其像慢动作回放一样拆解为关键帧序列 。




* **元认知循环（Metacognitive Prompting）：**
* 
**自我批判机制：** 要求模型在输出前先进行 `<scratchpad>` 思考或自我审查 。


* **具体检查点：**
* “检查：动作是否符合物理定律？” 


* “检查：本页对话量是否遮挡超过 30% 画面？” 


* “检查：是否存在时代穿帮（如古代出现手机）？” 




* 
**自动修正：** 发现错误后自动执行修正循环，而非输出错误结果 。





### 4. 推荐的 System Prompt 结构示例

根据文档建议，一个完整的 System Prompt 应包含以下 XML 封装的模块 ：

```xml
<system_prompt>
    <role_definition>
        你是一位严格遵循视觉逻辑的漫剧编剧。你不知道角色的内心想法，只能看到他们的动作。
    </role_definition>
    
    <series_bible>
        </series_bible>
    
    <constraints>
        <syntax> 使用标准 Fountain 格式 </syntax>
        <negative> 严禁使用心理动词（觉得、认为） </negative>
        <dialogue> 单个气泡不超过 30 字 </dialogue>
    </constraints>
    
    <instruction>
        1. 阅读输入文本。
        2. <thinking> 在草稿区进行节拍拆解与视觉化分析。 </thinking>
        3. 输出最终剧本。
    </instruction>
</system_prompt>

```
