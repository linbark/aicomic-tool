**Cursor**

下面给你一套**“逐章输入、逐步构建世界观与角色演变”**最贴合的总方案：它把“记忆”拆成**结构化真相库（可版本化）+ 向量语义库（可检索）+ 短期工作台（可迭代）**，并把“角色演变”从一开始就当作**时间轴/版本控制问题**来设计。

---

### 方案总览（你要的“最佳总方案”骨架）
- **核心思想**：把小说解析当成“持续集成（CI）”  
  每输入一章，就跑一条固定流水线：**抽取 → 对齐对比 → 生成变更集 → 写入记忆 → 质量校验 → 产出大纲/剧本资产**。
- **记忆分三层**（对应你两篇文档里的 Buffer / Vector 思路，但更“工程化可迭代”）：
  - **L0 短期工作台（Buffer / Workspace）**：当前章节处理的临时状态、推理草稿、冲突待办（会清洗）
  - **L1 结构化长期真相库（Canonical Store）**：世界观/角色/地点/组织/道具的**版本化记录**（可追溯、可回滚、可按时间段生效）
  - **L2 语义检索库（Vector Store）**：把 L1 的“可读摘要”与原文证据切片向量化，用于快速召回上下文（但不作为最终真相）

---

### 软件功能与模块划分（建议的“软解家构设计”）
- **Ingestion / Chapter Manager**
  - 管章节输入、分段、编号、元数据（章号、时间线位置、POV、地点线等）
- **Evidence Store（原文证据库）**
  - 存储“原文片段（带引用位置）”，作为所有设定的可追溯依据
- **Extraction Agents（抽取代理组）**
  - **世界观抽取器**：规则、科技/魔法体系、社会结构、禁忌、物理约束
  - **实体抽取器**：角色/地点/组织/道具/关系
  - **事件与状态变更抽取器**：发生了什么、谁获得/失去什么、谁受伤/立场变化
- **Diff & Merge Engine（对齐-对比-合并引擎）**
  - 把“本章抽取结果”与“既有真相库”做**对齐**（同一实体识别）→ **差异检测**（是否演变/矛盾/补充）→ 生成**变更集（ChangeSet）**
- **Timeline Manager（时间轴管理器）**
  - 专门管理你提到的“韩风 1-3、4-10 …；冰凝 5-7、8-12 …”这种**生效区间**
- **Consistency Supervisor（一致性监理）**
  - 用真相库规则做校验：设定冲突、物理不可能、角色外观漂移、称谓不一致
- **Output Producers（产出器）**
  - 大纲（Beat Sheet）→ 剧本（Fountain/结构化）→ 分镜提示词（受控词汇表/平台方言）

### 记忆工程：你想要的“公共记忆仓库 + 世界观迭代 + 角色时间轴”
这里建议你把“公共记忆仓库”拆成两部分：**结构化版本库（真相）+ 向量库（检索加速）**。

#### 1）结构化真相库（Canonical Store）：版本化实体 + 生效区间
- **实体（Entity）**：Character / WorldRule / Location / Organization / Item …
- **每个实体不是一条记录，而是一条“主干 + 多个版本切片（Snapshot）”**
- **每个版本切片都有生效区间**：`valid_from_chapter` 到 `valid_to_chapter`（可为空表示“至今有效”）
- **每个版本切片都有证据**：指向 Evidence Store 的原文引用

> 这样你要的“韩风 1-3、4-10”本质就是：同一角色 `HanFeng` 的两个 Snapshot，分别覆盖不同章节区间。

#### 2）动态剧情库（Dynamic Plot Store）：只存“状态变更”，不存流水账
- 每章结束生成：**本章事件表 + 状态变更表**（例如：受伤、获得道具、关系变化、阵营变化）
- 动态库用于后续生成大纲/剧本时回答：  
  “此刻他是否受伤？”“芯片是否已获得？”——这是向量库很难稳定保证的

#### 3）向量语义库（Vector Store）：服务“召回”，不当“真相”
向量库存三类东西（都带强元数据，便于过滤）：
- **Entity Summary Chunk**：角色/世界观的“当前摘要”与“各版本摘要”
- **Evidence Chunk**：原文片段向量化（用于回证据）
- **Chapter Summary Chunk**：每章结构化总结的自然语言版本（用于快速语义检索）

检索时必须支持按元数据过滤：
- `type`: `character | world_rule | item | event | evidence`
- `entity_id`
- `chapter_range`（或 `chapter <= x` 过滤）
- `confidence`、`source`（抽取器/人工确认）

### 逐章工作流（你第4点的“提取→完善→判断变化→更新→生成大纲”落地版）
每输入一章，跑这个固定流程：

1. **加载上下文（分层检索）**
   - 从真相库取：**世界观规则（当前有效）**、本章涉及角色的**最近有效版本切片**
   - 从动态库取：与本章相关的**已发生事件/状态**
   - 从向量库补：语义相近证据片段（但只作参考）

2. **本章抽取（结构化输出）**
   - 抽取：新实体、实体新属性、规则补充、事件、状态变更
   - 同时输出：每条抽取的**证据引用**

3. **对齐与差异检测（关键）**
   - **同一实体识别**：别名/称谓/指代合并（先规则后语义）
   - **差异分类**（建议至少四类）：
     - **补充**：原设定不完整 → 增补字段
     - **演变**：角色外观/性格/能力随剧情变化 → 新建版本切片（开新区间）
     - **矛盾**：与既有设定冲突 → 进入待裁决队列（可让监理或人工确认）
     - **不确定**：证据弱/描写暧昧 → 标低置信度，不立即覆盖真相

4. **生成 ChangeSet 并写入记忆**
   - **世界观**：规则允许增量完善；若冲突，生成“候选规则版本”而不是直接改掉旧规则
   - **角色**：若判断为演变 → 关闭旧切片 `valid_to = chapter-1`，开启新切片 `valid_from = chapter`
   - **动态事件**：写入事件表与状态变更表

5. **一致性监理**
   - 用世界规则/角色“不可变视觉核”（如果你有 Visual DNA）去检查：本章抽取是否造成逻辑破坏
   - 输出修正建议或待办（进入 Buffer 的 TODO）

6. **产出（面向漫剧）**
   - 生成：本章 Beat Sheet / 场景列表 / 情绪曲线 / 视觉重点
   - 再生成：剧本（Fountain）与分镜提示词（受控词汇表 + 平台适配）

### 你最关心的：世界观“不是一开始设定好”的处理方式
- **世界观规则也做版本化**，但通常规则变更更少，更多是“逐步补全”：
  - 规则条目可以有 `status`: `hypothesis | confirmed | retconned`
  - 当后文推翻前文：不要覆盖删除，而是标记旧规则 `retconned`，并记录“被哪章哪句证据推翻”
- 生成剧本时的规则选择：
  - 默认只取 `confirmed` + 当前章节之前生效的版本
  - `hypothesis` 只能作为“可能性”，不能当硬约束
